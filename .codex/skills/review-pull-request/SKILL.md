# Review a Pull Request

1. Read the PR and linked GitHub Issue, including the issue's acceptance criteria.
2. Inspect the changed files and full diff. Check issue scope, correctness, regressions, unnecessary complexity, and the repository's code-quality guidance in `AGENTS.md`.
3. Inspect relevant validation results and assess whether they cover the change.
4. Report actionable findings first, separating blockers from non-blocking suggestions. Focus on correctness, maintainability, scope, or testing concerns rather than stylistic nitpicks handled by tooling.
5. Give a clear recommendation: merge or changes requested.
